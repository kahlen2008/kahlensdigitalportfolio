Project Journey

A structured walkthrough of my contribution across each phase.

01

The Problem

Intergenerational engagement programmes in Singapore are often short-term, manually coordinated, and difficult to sustain. Many activities between youths and seniors rely on one-off workshops or informal arrangements, resulting in limited continuity and minimal measurable impact.

Core Challenge

No structured system for event coordination—manual tracking led to double-bookings, missed registrations, and lost community suggestions.

Project Scope

Build a complete Event & Booking Management System with admin moderation, user registration, and a community-driven suggestion pipeline.

02

My Role

As one of the full-stack developers on Bridgify, I was assigned ownership of the Event & Booking Management System — the platform's most critical module. I handled the full feature lifecycle, from database schema design to frontend interactivity.

Backend

Designed Flask routes for event CRUD, booking management, suggestion submissions, and admin approval workflows.

Frontend

Built modal-based UI for event creation, suggestions, and admin review with Jinja templating and JavaScript interactions.

03

Solution Design

I designed an end-to-end workflow that transforms community suggestions into published events through a structured moderation pipeline.

User Submits Suggestion

Community members propose event ideas through a modal form. Submission is stored with "Pending" status.

Admin Reviews in Dashboard

Administrators access a dedicated suggestions panel to review, approve, or reject proposals.

Auto-Fill Event Creation

Upon approval, the title and description auto-populate the event creation form via hidden input fields and Jinja template variables.

Event Published to Calendar

Admin sets date, time, and location. Event commits to the database and appears on the user calendar immediately.

Database Architecture

Implemented a relational SQLite database with separate tables for Events, Bookings, and Suggestions with appropriate fields and relationships.

Validation & Integrity

Built server-side form validation to prevent invalid submissions. Implemented date/time constraints so past events cannot be created.

04

Work Process

Building a production-style system required iterative development, debugging, and adapting to unexpected constraints.

Development Approach

Iterative process: build core CRUD first, then layer on the suggestion workflow, admin panel, and validation logic.

Challenges

Database migration issues, modal state management across multiple forms, and real-time update synchronisation.

Problem-Solving

Custom DatabaseHelper class for SQL abstraction, robust status-tracking for suggestions, and cascading UI updates.

Quality Assurance

Rigorous form validation, slot availability checks, input sanitisation, and password-protected admin access.

05

Outcomes & Impact

My implementation transformed event coordination from a manual process into a structured digital system.

Reduced Workload

Automated event creation directly from community suggestions eliminated manual data entry and prevented human errors like double-booking.

Scalable Architecture

Designed with a modular codebase and clean relational database schemas, allowing new features to be integrated easily as the platform scales.

Community Driven

The dedicated suggestion pipeline empowers members to actively propose, vote on, and shape their own intergenerational programmes.

Measurable Impact

Admin dashboards provide real-time visibility into booking statuses and event analytics, turning scattered events into measurable data.
